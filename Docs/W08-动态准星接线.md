# W08 动态准星｜蓝图接线与五枪实践

日期：2026-10-16。当前要求R20261016-3，叠加J在本执行窗口确认的四线、累计上限、切枪平滑与跨项目复用要求；J“可以开始干活吧”授权本片真实C++实施。源码已安装并通过真实Dust2Editor编译、32项局部原生测试；本文件是J接线和PIE步骤，未登记为已操作或已验收。

## 本片实际实现

- 通用：`DynamicCrosshairWidget`原生绘制四条独立短线；`CrosshairDisplayMath.h`处理普通跟随、有限时间SmoothStep过渡、移动目标、过渡重启和截止缩短。不读玩家、枪名、弹药或输入。
- Dust2：`DustCrosshairComponent`读取显式传入的库存/表现组件/射击相机与拥有者移动事实，投影当前武器的同源总散布。一个PostUpdateWork显示Tick，无开火绑定、无新Timer、不写Visibility、不写散布。合法瞄准显隐继续沿W05。
- `WeaponRuntime`新增“获取当前总散布角”；与真实射线共用状态选角和Clamp计算。弹道仍用本发冻结值，UI用当前下一发精度。
- 原有表现换枪Reset改为只清方向后坐、本发缓存，不清连续射击散布；原完整Reset/换弹/重建语义保留。切到后台的武器随世界时间恢复。
- 掉落状态增加腰射/瞄准累计值、两套成功射击年龄和捕获时间；拾取重建保留地面经过的恢复时间。没有新增检查点字段，没有改变扣弹/库存/首次拔枪/丢弃事务顺序。
- 新增只读拔枪剩余时间查询，仅供缩短视觉过渡；既有完整动作门禁不变。

## 先完成这批接线

以下在当前实际玩家/HUD路径操作，不新建测试玩家。资产名带Test不代表它不是当前正式玩法使用路径。

### 1. 保存蓝图回退

保存本片修改前的`WBP_Crosshair`、`WBP_HUD`和实际玩家蓝图副本到你惯用的回退位置，继续编辑当前玩法使用的原资产。原生源码备份已在`实施前基线/Source/Dust2`，无需你覆盖源码。

重新打开工程，让它加载本轮新编译DLL。不要用旧编辑器进程的Live Coding状态判断新反射类是否已加载。

### 2. 把已有准星改为通用四线显示

1. 打开`WBP_Crosshair`，Class Settings（类设置）→Parent Class（父类）选择`DynamicCrosshairWidget`。仍使用原来的WBP资产及HUD引用，不另建一套准星。
2. 把现有`TXT_Crosshair`文本“+”设为Hidden，保留作回退，避免和新四线重叠。无需手动新增四个Image：四条线由原生父类绘制，分别随X/Y间距移动，长度和厚度不随扩散缩放。
3. 在Class Defaults确认：`MinimumGap=(3,3)`、`LineLength=7`、`LineThickness=1.75`、`CrosshairColor=白色`。数值均为UMG布局单位，是首版外观起点。中心不新增圆点。
4. 在`WBP_HUD`选中已有`WBP_Crosshair`：让该子Widget覆盖HUD游戏画面区域。若父级是Canvas，锚点四向拉伸、四边Offset=0、关闭AutoSize；若父级是Overlay，水平/垂直均Fill。不要把它保持成只容纳旧“+”的极小尺寸；原生四线按子Widget中心绘制。
5. 保留WBP_Crosshair作为独立显示对象，武器名称提示/弹药/命中提示不移进这个控件。编译保存。

### 3. 给玩家添加Dust2接入组件

在当前玩家蓝图添加`DustCrosshairComponent`组件，建议组件实例名`DynamicCrosshair`（拟新增）。不要删或替换现有WeaponInventory/WeaponPresentation/移动/相机组件。

组件首版参数：

| 参数 | 首版值 | 含义 |
| --- | --- | --- |
| 普通间距跟随速度 / FollowRate | 20 | 只决定画面跟随的柔和程度，不决定真实精度恢复 |
| 换枪过渡最长秒数 / SwitchTransitionSeconds | 0.18 | 从当前显示值向新枪状态过渡的最长时间 |
| 拔枪完成前提前秒数 / FinishBeforeDrawSeconds | 0.04 | 有真实最终拔枪实例时，让过渡提前结束 |

### 4. HUD暴露当前准星实例

在`WBP_HUD`确认嵌入的WBP_Crosshair是变量（Is Variable）。新增一个蓝图函数，例如`GetDynamicCrosshairWidget`（本片拟新增），返回该WBP_Crosshair实例，返回类型可直接用`DynamicCrosshairWidget Object Reference`。

不返回Class，不新Create Widget。使用屏幕上已有那一个实例。

### 5. 在现有初始化末尾调用一次

复用玩家已有BeginPlay初始化链。在以下步骤均已完成后调用一次：

```text
已有创建WBP_HUD → 保存HUDRef → Add to Viewport
已有 Initialize Player Inventory Bridge 完成
已有 Initialize Aim State 完成
→ HUDRef.GetDynamicCrosshairWidget
→ DynamicCrosshair.初始化动态准星
```

“初始化动态准星”实参：

| 引脚 | 接什么 |
| --- | --- |
| Target | 刚添加的DynamicCrosshair组件 |
| Widget | HUDRef返回的已有WBP_Crosshair实例 |
| Inventory | 当前Initialize Player Inventory Bridge使用的同一个WeaponInventoryComponent |
| Presentation | 当前Initialize Aim State使用的同一个WeaponPresentationComponent |
| Shooting Camera | 现有FireOnceAndUpdateAmmo取得射线起点/前向的`Fps`相机 |

不要复制另一条BeginPlay，不在Tick重复初始化。Return Value应为True；若为False，先核对传入的都是当前玩家实例的对象，以及Create Widget的Owning Player是否接当前PlayerController。首次画面布局尚未完成时，组件会等待有效几何尺寸，不需要Delay或轮询初始化Timer。

### 6. 保留旧瞄准显隐链

保持现有：

```text
ReceiveAimStateChanged(Aiming)
→ HUDRef.SetHipCrosshairVisible(NOT Aiming)
```

不要在新组件Tick或原始右键输入中再次SetVisibility。现有切换瞄准清掉旧命中提示的处理保留。隐藏期间组件仍更新过渡，恢复显示不会从上一把枪间距重演。

切枪/丢枪不需要新接“开始过渡”事件：组件绑定已有库存装备变化事件，并核对当前武器；实际最终拔枪剩余时间和正常结束事件用于收束过渡。所有绑定在停止/重初始化/EndPlay时解除。

若你销毁并重建HUD，给新Widget再调用一次初始化即可，旧绑定会先解除。若只临时隐藏结果界面下的原HUD，不需额外停止或重建组件。组件不替旧结果/死亡UI链决定可见性。

## 五枪配置：改前现值与首版建议

改前数据来自本轮自动化只读加载真实资产，原始`[W08Asset]`/`[W08Recoil]`行保存在`Automation.log`；不是C++默认值，也不是旧建议。资产仍未被本轮工具修改。

只调整`枪械配置|腰射连续射击散布`这一组；腰射基础状态、右键独立散布、后坐轨迹/倍率、射速/模式/伤害/拉栓门禁先保持现值。调整以下参数会改变腰射实际随机精度，准星随同源数据变化。

| 枪／资产 | 改前：启用，每发／上限／延迟／速度 | 首版建议：启用，每发／上限／延迟／速度 |
| --- | --- | --- |
| AK105 / DA_AK105Definition | 开，0.10°／1.50°／0.20s／2.00°每秒 | 开，0.20°／1.50°／0s／1.00°每秒 |
| TR15 / DA_TR15Definition | 开，0.10°／1.50°／3.00s／2.00°每秒 | 开，0.14°／1.20°／0s／1.00°每秒 |
| R08 / DA_R08Definition | 开，1.00°／5.00°／0.35s／2.00°每秒 | 开，0.80°／3.00°／0s／1.30°每秒 |
| Viper / DA_ViperDefinition | 开，1.00°／5.00°／0.10s／2.00°每秒 | 开，0.22°／1.40°／0s／1.20°每秒 |
| SRM-12 / DA_SRM-12Definition | 关，0.15°／0.80°／0.20s／2.00°每秒 | 开，0.60°／1.20°／0s／1.20°每秒 |

目录均为`/Game/Code/Texts/对应枪目录/`。SRM路径包含短横线，名称为`DA_SRM-12Definition`。

这些是J授权方向下供实践的首版建议，未写入资产、未获PIE手感确认。先完成AK接线并验证，再改其余四枪，不在HUD里用枪名Switch写死这些数值。

协调依据：零延迟使两枪之间也回收；普通持续射击时每枪净增长约为`每发增加－恢复速度×实际射击间隔`，必须为正才能逐渐撑大。AK普通间隔0.10s、TR15普通0.075s/三连发0.05s、R08 0.30s、Viper 0.10s、SRM 1.40s为本轮读取值。上述首版让AK约14发、TR15普通约18发接近上限，R08快速连点约7发，Viper约13发；具体Burst组间恢复与实际输入会改变发数。SRM一发增加0.6°、约0.5s恢复完，短于下一次合法开火间隔，适合单发与拉栓节奏，不为连射累积修改射速。

满累计回收时间（零延迟）依次约1.5s/1.2s/2.31s/1.17s/1s；SRM正常单发不会撑到设定上限。TR15现有镜头后坐比AK更强、回落更慢，故这里没有机械用后坐倍率计算随机散布；两者协调节奏但保持各自职责。

特别保留：SRM当前腰射基础为静止8°、移动3°、静步1°、空中12°，与其他枪不同；本片不顺手重做已接受基础散布平衡。其右键独立散布及零精度约束保持原配置，准星仍隐藏。

## 一批运行检查

先AK：

1. 静止→走动→静步→跳起/落地→停步：四线保持中心，间距随状态改变；静步不固定等于0。
2. 单发增加、快速连射累计、上限封顶、两枪之间回收、停火恢复。观察恢复过程而非要求每枪落点对应线端。
3. 空仓、射速冷却、换弹与切枪拒绝不增加成功射击扩散；已有扩散仍可回收。
4. A还在恢复时Q切B：四线从当前显示值平滑接到B，并尽量在拔枪结束前到位；切回A显示其自身已恢复后的值。反复合法切换无跳回旧起点。
5. A还在恢复时G丢弃：平滑接B；尽快捡回A，其散布按经过的时间恢复，不因丢枪直接归零。注意自动拾取/自动填槽规则照旧。
6. 合法右键隐藏、松开恢复；奔跑待瞄不会误隐藏，松键取消正常；瞄准换弹沿W05。

再TR15/R08/Viper/SRM复用同一组件和控件，只改对应配置，验证区别及不串枪。最后核死亡/重试无失效引用/重复绑定、空手旧显示约定与武器名称提示保留，以及16:9/4:3两种窗口比例的中心和稳定间距。

编译保存相关蓝图后集中反馈：提供初始化接线、改后Designer/默认值和遇到的具体运行差异；已通过项用一句话确认，不必逐节点回执。

## 复用到其他UE项目

通用文件：`CrosshairDisplayMath.h`与`DynamicCrosshairWidget.h/.cpp`，加新项目的UMG/SlateCore/Slate模块依赖并更换导出宏。它们没有Dust2类型或枪名判断。

其他项目只需自己的接入层提供目标局部间距，调用`Advance(Target,DeltaSeconds,FollowRate)`，换枪时`BeginTransition(Duration)`，必要时`ConstrainRemainingTime`，把输出传给`SetCrosshairGap`。本项目`DustCrosshairComponent`是接入示例，不要求把Dust2武器/库存系统一起搬过去。

没有实际第二项目运行证据；本轮证明的是依赖隔离、真实编译和局部自动测试，不称已跨项目验收。
